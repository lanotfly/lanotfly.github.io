Deployments, ReplicaSets, and scaling

Declare the desired number of replicas and let Kubernetes reconcile the running workload toward that state.

1. The controller chain

A Deployment manages a ReplicaSet; the ReplicaSet maintains the requested number of matching Pods. You normally update the Deployment rather than creating ReplicaSets or Pods manually.

2. Deployment example

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.27
          ports:
            - containerPort: 80

3. Rollouts and scaling

kubectl apply -f deployment.yaml
kubectl rollout status deployment/web
kubectl rollout history deployment/web
kubectl rollout undo deployment/web
kubectl scale deployment/web --replicas=5
  • Readiness determines whether a Pod should receive Service traffic.
  • Rolling updates replace Pods gradually; tune maxSurge and maxUnavailable to balance capacity and availability.
  • Horizontal Pod Autoscaler adjusts replicas based on configured metrics; it does not create node capacity by itself.
