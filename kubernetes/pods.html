Pods: the smallest deployable unit

A Pod wraps one or more tightly coupled containers and gives them a shared network identity and storage context.

1. What is a Pod?

A Pod is the smallest object Kubernetes schedules onto a node. Most application Pods contain one main container; tightly coupled sidecars may share the same Pod when they need to communicate over localhost or share volumes.

2. Minimal Pod manifest

apiVersion: v1
kind: Pod
metadata:
  name: web
  labels:
    app: web
spec:
  containers:
    - name: nginx
      image: nginx:1.27
      ports:
        - containerPort: 80

3. Lifecycle and design rules

  • Pods are replaceable, not durable identities. A replacement Pod usually has a new name and IP.
  • Use Deployments for stateless workloads instead of managing individual Pods by hand.
  • Use labels to group Pods and selectors to target them.
  • Do not put unrelated applications in one Pod merely because they share a node.

4. Useful commands

kubectl get pods -o wide
kubectl describe pod web
kubectl logs web
kubectl exec -it web -- sh

SRE note: when a Pod is not healthy, inspect its events, container status, logs, probes, resource limits, and node placement before restarting it.
