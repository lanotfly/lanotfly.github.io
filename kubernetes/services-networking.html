Services, DNS, and network traffic

A Service provides a stable virtual endpoint for a changing set of Pods, selected by labels.

1. Why Services exist

Pods can be replaced and their IP addresses can change. A Service selects matching Pods and gives clients a stable DNS name and virtual IP. EndpointSlices record the backend endpoints.

2. ClusterIP Service

apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
    - name: http
      port: 80
      targetPort: 8080

3. Common Service types

  • ClusterIP: internal cluster access; the default.
  • NodePort: exposes a port on each node, often used in simple or lab setups.
  • LoadBalancer: asks the environment/provider to provision an external load balancer.
  • Ingress / Gateway API: HTTP routing is handled by a controller or gateway implementation; creating the routing object alone may not install that implementation.

4. Debugging traffic

kubectl get svc,endpointslices
kubectl describe service web
kubectl get pods -l app=web --show-labels
kubectl run curl --rm -it --image=curlimages/curl -- sh

Check selectors, targetPort, readiness, DNS, NetworkPolicy, and whether the application actually listens on the expected interface and port.
