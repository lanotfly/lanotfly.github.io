4. Greedy & Dynamic Programming — Local Choices vs States

Greedy algorithms commit to local choices. Dynamic programming evaluates states and reuses answers to overlapping subproblems. The challenge is proving the model, not merely coding it.

1. Greedy

A greedy choice is safe only when there is a proof that some optimal solution includes it. Common proof techniques include an exchange argument and showing a structural property that makes local choices compatible with a global optimum.

Example: to select the maximum number of non-overlapping intervals, sort by end time and repeatedly choose the next interval that starts after the last selected one ends.

def max_non_overlapping(intervals):
    end = float("-inf")
    count = 0
    for start, finish in sorted(intervals, key=lambda x: x[1]):
        if start >= end:
            count += 1
            end = finish
    return count

2. Dynamic programming recipe

  1. State: what information uniquely identifies a subproblem?
  2. Transition: how do smaller states combine?
  3. Base case: what can be answered immediately?
  4. Order: in what order are dependencies computed?
  5. Answer: which state or combination is the requested result?

3. Example: climbing stairs

To reach step n, the final move came from n−1 or n−2. Thus dp[n] = dp[n-1] + dp[n-2], with the first states defined explicitly.

def climb_stairs(n: int) -> int:
    a, b = 1, 1
    for _ in range(n):
        a, b = b, a + b
    return a

The iterative version takes O(n) time and O(1) extra space. The DP table is unnecessary because each state depends only on the previous two.
