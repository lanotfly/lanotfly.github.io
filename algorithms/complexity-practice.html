6. Complexity & Interview Practice — Analyze Before Optimizing

Big-O describes how resource use grows with input size. It is a model for comparing approaches, not an exact prediction of wall-clock time.

1. Complexity quick reference

ComplexityTypical shapeExample
O(1)Constant workArray index access
O(log n)Repeatedly halve search spaceBinary search
O(n)One passScan array
O(n log n)Divide and combine / comparison sortMerge sort
O(n²)All pairsNested loop over n items
O(2ⁿ), O(n!)Enumerate subsets or permutationsMany brute-force searches

2. Time and space

State time and auxiliary space separately. A recursive algorithm may have O(n) stack space even if it allocates no explicit array. Output storage is often excluded from auxiliary space, but say which convention you are using.

3. Interview explanation framework

  1. Restate the input, output, and constraints.
  2. Give a simple brute-force approach and its cost.
  3. Identify the bottleneck and select a pattern.
  4. State the invariant or correctness argument.
  5. Walk through one normal example and one edge case.
  6. Analyze time and space; mention assumptions.
  7. Test empty input, duplicates, boundary values, and large inputs.

4. Suggested learning sequence

Start with arrays, strings, hash maps, two pointers, sliding windows, and prefix sums. Then learn binary search, stacks and queues, linked lists, trees, heaps, graphs, backtracking, greedy, and DP. Revisit missed problems after several days to test recall.

5. SRE-oriented examples

  • Use hash maps to aggregate log events by status code.
  • Use heaps to maintain top-K latency or error contributors.
  • Use graphs to model service dependencies and impact propagation.
  • Use sliding windows for rolling error rates and latency summaries.
  • Use binary search on a monotonic threshold when tuning capacity or finding a first failing version.
