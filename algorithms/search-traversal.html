2. Search & Traversal — Binary Search, BFS and DFS

Search algorithms reduce the candidate space or systematically explore states. The key is to identify the structure that makes a search safe and efficient.

1. Binary search

Binary search applies when the data is sorted or when a yes/no predicate is monotonic. Maintain a range that still contains the answer and discard half after each comparison.

def lower_bound(nums: list[int], target: int) -> int:
    left, right = 0, len(nums)
    while left < right:
        mid = left + (right - left) // 2
        if nums[mid] < target:
            left = mid + 1
        else:
            right = mid
    return left

lower_bound returns the first index whose value is at least target, or len(nums) if none exists. Time O(log n), extra space O(1).

2. Breadth-first search (BFS)

BFS uses a queue and explores by distance in number of edges. In an unweighted graph, the first time a node is discovered gives its shortest edge-count distance.

from collections import deque

def bfs(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt not in distance:
                distance[nxt] = distance[node] + 1
                queue.append(nxt)
    return distance

Mark nodes when enqueued, not after processing, to avoid duplicate queue entries. Complexity is O(V+E) for adjacency-list graphs.

3. Depth-first search (DFS)

DFS follows a path as far as possible before backtracking. It is useful for reachability, connected components, cycle detection, and tree traversal.

def dfs(graph, start):
    seen = set()
    stack = [start]
    while stack:
        node = stack.pop()
        if node in seen:
            continue
        seen.add(node)
        stack.extend(nxt for nxt in graph[node] if nxt not in seen)
    return seen

Use an explicit stack when recursion depth could exceed the language limit. BFS is usually the simpler choice for shortest paths in unweighted graphs; DFS does not guarantee a shortest path.

4. Search-space checklist

  • Is the input sorted, or is the answer predicate monotonic?
  • Is the graph weighted? If weights are non-negative, Dijkstra may be appropriate.
  • Do you need shortest distance, reachability, or all possible paths?
  • Are cycles possible? Track visited states.
  • Does a state need more than a node ID, such as (position, keys collected)?
