Algorithms & LeetCode Patterns

Most interview questions are variations on a smaller set of ideas. The goal is not to memorize hundreds of solutions; learn to recognize the shape of a problem, choose a pattern, and explain its time and space complexity.

A quick pattern map

Two pointers

Signal: sorted array, pair sum, palindrome, or comparing both ends.

Idea: move one or both pointers according to a condition, often avoiding a nested loop.

Typical cost: O(n) time, O(1) extra space.

Practice: Two Sum II, Valid Palindrome, Container With Most Water, 3Sum.

Sliding window

Signal: a contiguous substring/subarray and a condition about its contents.

Idea: expand the right edge; shrink the left edge when the window becomes invalid.

Typical cost: often O(n) time because each pointer advances at most n times.

Practice: Longest Substring Without Repeating Characters, Minimum Size Subarray Sum, Permutation in String.

Hash map / set

Signal: count frequencies, detect duplicates, or ask whether a value has appeared before.

Idea: trade O(n) extra memory for expected O(1) membership or lookup.

Practice: Two Sum, Group Anagrams, Longest Consecutive Sequence, Top K Frequent Elements.

Prefix sum

Signal: many range-sum queries, subarrays that sum to k, or cumulative totals.

Idea: store cumulative values; combine prefix sums to derive a range or use a map of previously seen sums.

Practice: Range Sum Query, Subarray Sum Equals K, Product of Array Except Self (related prefix/suffix idea).

1. Array and string patterns

Two pointers — converge or move together

def two_sum_sorted(nums: list[int], target: int) -> list[int]:
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left, right]
        if total < target:
            left += 1
        else:
            right -= 1
    return []

Why it works: sorted order lets each comparison eliminate an entire set of impossible pairs. On an unsorted array, sorting may change the original indices and adds O(n log n) time.

Sliding window — maintain a valid range

def longest_unique_substring(s: str) -> int:
    last_seen = {}
    left = best = 0
    for right, char in enumerate(s):
        if char in last_seen and last_seen[char] >= left:
            left = last_seen[char] + 1
        last_seen[char] = right
        best = max(best, right - left + 1)
    return best

2. Search, traversal, and ordering

Binary search

Use when the search space is sorted or a monotonic yes/no condition exists. Halve the candidate range each step: O(log n) time.

Practice: Binary Search, Search in Rotated Sorted Array, Find Minimum in Rotated Sorted Array, Koko Eating Bananas (“binary search on answer”).

BFS — breadth-first search

Use a queue to visit nodes level by level. Finds shortest path by number of edges in an unweighted graph. O(V + E).

Practice: Binary Tree Level Order Traversal, Rotting Oranges, Word Ladder.

DFS — depth-first search

Use recursion or an explicit stack to explore a path deeply before backtracking. Useful for connected components, reachability, and tree paths. O(V + E).

Practice: Number of Islands, Clone Graph, Path Sum, Course Schedule (with cycle detection).

Sorting

Sorting often simplifies a problem by creating order, enabling two pointers, or grouping equal values. Comparison sorting is typically O(n log n).

Practice: Merge Intervals, Meeting Rooms, Sort Colors, Largest Number.

3. Recursion, backtracking, and divide & conquer

Recursion

A function solves a smaller version of the same problem. Every recursive solution needs a base case and progress toward it. Space complexity includes the call stack, often O(depth).

def factorial(n: int) -> int:
    if n <= 1:             # base case
        return 1
    return n * factorial(n - 1)  # smaller subproblem

Backtracking

Build a candidate, explore it, then undo the choice. Use when you need to enumerate combinations, permutations, paths, or valid configurations. The number of candidates can grow exponentially.

Practice: Subsets, Permutations, Combination Sum, N-Queens, Word Search.

Divide and conquer

Split the input into smaller subproblems, solve each, then combine the results. Merge sort is the classic example: O(n log n) time and O(n) auxiliary space.

4. Greedy and dynamic programming

Greedy

Choose the best-looking local option at each step. Greedy is correct only when the problem has a proof-friendly property (such as an exchange argument or matroid structure); local choices do not always produce a global optimum.

Practice: Jump Game, Gas Station, Non-overlapping Intervals, Partition Labels.

Dynamic programming (DP)

Use when subproblems overlap and a recurrence combines their answers. Define the state, transition, base case, and evaluation order before coding. Memoization is top-down; tabulation is bottom-up.

Practice: Climbing Stairs, House Robber, Coin Change, Longest Increasing Subsequence, Edit Distance.

Monotonic stack / queue

Maintain elements in increasing or decreasing order to answer “next greater/smaller” or sliding-window maximum questions in linear time.

Practice: Daily Temperatures, Largest Rectangle in Histogram, Next Greater Element, Sliding Window Maximum.

Heap / priority queue

Repeatedly access the current minimum or maximum without fully sorting all items. Useful for top-K, scheduling, and merging sorted streams.

Practice: Kth Largest Element, Top K Frequent Elements, Find Median from Data Stream, Merge K Sorted Lists.

5. Graph-specific patterns

  • Topological sort: order tasks with dependencies in a directed acyclic graph. Practice: Course Schedule, Alien Dictionary.
  • Union-Find: efficiently track connected components as edges are added. Practice: Number of Provinces, Redundant Connection.
  • Dijkstra: shortest paths with non-negative edge weights, usually with a min-heap. Practice: Network Delay Time, Path With Minimum Effort.
  • Trie: prefix-based lookup for dictionaries and autocomplete. Practice: Implement Trie, Word Search II.

7. A practical LeetCode study order

  1. Arrays, strings, hash maps, and sets.
  2. Two pointers, sliding window, prefix sums, and sorting.
  3. Binary search, linked lists, stacks, queues, and monotonic stacks.
  4. Trees: DFS, BFS, BST properties, recursion.
  5. Heaps, intervals, graphs, topological sort, and union-find.
  6. Backtracking, greedy, and dynamic programming.

For each problem: explain the brute-force approach first, identify the bottleneck, name the pattern, state the invariant, then give time and space complexity. Revisit missed problems after a few days rather than only increasing the problem count.
