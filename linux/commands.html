Essential Linux commands

A practical command reference for navigating a Linux host, inspecting files and logs, and diagnosing common SRE issues. Replace example paths and process names with values from your system.

1. Navigation and listing

CommandPurpose
pwdPrint the current working directory.
ls -lahList files, including hidden files, with readable sizes and details.
cd /var/logChange to a directory.
find /etc -name '*.conf'Search recursively for files matching a name pattern.

2. Read files and inspect logs

cat /etc/os-release
less /var/log/syslog
head -n 20 app.log
tail -n 100 app.log
tail -f app.log
grep -n "ERROR" app.log
grep -Rni "listen" /etc
  • less is usually better than cat for large files; press q to quit.
  • tail -f follows new lines as they arrive. Press Ctrl+C to stop.
  • grep -Rni searches recursively, ignores case, and prints line numbers.
  • Log locations differ: systemd-based hosts often support journalctl even if a traditional syslog file is absent.

3. Create, copy, move, and remove files

mkdir -p ~/lab/logs
touch ~/lab/notes.txt
cp source.txt backup.txt
mv old-name.txt new-name.txt
rm -i unwanted.txt

Warning: file removal can be permanent. Check the current directory with pwd and verify the target with ls before removing anything. Avoid force options or broad paths unless you fully understand the effect.

4. Permissions and ownership

ls -l script.sh
chmod u+x script.sh
chmod 640 config.txt
chown app:app config.txt
id
whoami

Permissions describe read (r), write (w), and execute (x) access for owner, group, and others. chmod 640 gives the owner read/write, the group read, and others no access. Use sudo only when elevated privileges are necessary.

5. Disk, memory, and CPU

df -h
du -sh /var/log
free -h
uptime
top
ps aux
ps -ef
  • df -h reports filesystem space; du estimates space used by files/directories.
  • free -h summarizes memory and swap; Linux may use otherwise-free memory for caches.
  • uptime shows uptime and load averages; interpret load in the context of CPU count and I/O wait.
  • ps is a snapshot; top is interactive.

6. Processes and services

pgrep -a nginx
kill -TERM 1234
systemctl status nginx
systemctl restart nginx
journalctl -u nginx --since "30 minutes ago"
journalctl -u nginx -f

Service commands assume systemd and a service named nginx. Prefer a graceful TERM signal over force-killing a process. Before restarting a production service, check impact, current status, logs, and the applicable runbook.

7. Network troubleshooting

ip addr
ip route
ss -lntup
curl -I https://example.com
curl -v https://example.com
getent hosts example.com
ssh user@server.example.com
  • ip addr shows interfaces and addresses; ip route shows routing.
  • ss -lntup lists listening TCP/UDP sockets; showing process details may require elevated privileges.
  • curl -I requests response headers; curl -v provides connection diagnostics.
  • getent hosts checks name resolution through the system's configured name-service path.

8. Help and command composition

man find
grep --help
command -v python
some-command > output.txt
some-command >> output.txt
some-command 2> error.txt
some-command | grep "ERROR"
echo $?

> overwrites output, >> appends, and 2> redirects standard error. A pipe (|) sends one command's standard output to another command. $? contains the most recent command's exit status; 0 conventionally means success.

Suggested SRE troubleshooting sequence

  1. Confirm the symptom: capture the exact error, time, host, and affected service.
  2. Check capacity: uptime, free -h, df -h, and relevant du output.
  3. Check process and service state: ps, systemctl status, and ss -lntup.
  4. Read recent evidence: journalctl, application logs, and service events.
  5. Make one controlled change: follow the runbook, then verify health and record the result.
