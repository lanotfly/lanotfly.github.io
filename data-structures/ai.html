AI Foundations — From Tokens to Agents

This visual guide connects modern AI concepts to familiar computer-science building blocks: arrays, vectors, graphs, search, and computation. Start with the big picture, then explore how each piece fits together.

1. The core concepts

🔤 Tokens

Small text units mapped to integer IDs. A token may be a word, part of a word, punctuation, or whitespace-related unit.

CS connection: token IDs are indices into a vocabulary array.

📐 Embeddings

Dense numeric vectors that represent tokens, passages, images, or other items in a learned space.

CS connection: vectors are arrays; similarity search is a nearest-neighbour problem.

🧠 Neural network

A parameterized computation that transforms vectors through layers. Training adjusts parameters to reduce a loss objective.

CS connection: a computation graph with tensor operations and gradients.

🎯 Attention

A mechanism that lets each position combine information from other positions, weighted by relevance computed from the input.

CS connection: pairwise scores, matrix multiplication, and weighted aggregation.

🔎 Retrieval (RAG)

Find relevant external passages, then provide them as context to a model before it answers.

CS connection: indexing, ranking, filtering, and joining retrieved data with a prompt.

🛠️ Agents

Systems that use a model to choose actions, call tools, observe results, and continue toward a goal.

CS connection: a state machine or control loop with tools and explicit stopping conditions.

3. Vector similarity in Python

Embeddings are often compared with cosine similarity. The score is high when two non-zero vectors point in similar directions. This tiny example uses NumPy:

import numpy as np

def cosine_similarity(a, b):
    a = np.asarray(a, dtype=float)
    b = np.asarray(b, dtype=float)
    denom = np.linalg.norm(a) * np.linalg.norm(b)
    if denom == 0:
        return 0.0
    return float(np.dot(a, b) / denom)

cat = [0.9, 0.1, 0.2]
kitten = [0.85, 0.15, 0.25]
car = [0.1, 0.8, 0.7]

print(cosine_similarity(cat, kitten))
print(cosine_similarity(cat, car))

The numbers above are illustrative vectors, not real model embeddings. In a real application, an embedding model generates the vectors for you.

4. How RAG works

  1. Prepare: split documents into chunks and calculate an embedding for each chunk.
  2. Index: store chunk text, metadata, and vectors in a searchable index.
  3. Retrieve: embed the question and find relevant chunks, optionally using keyword and metadata filters too.
  4. Generate: place the question and retrieved evidence in the model context.
  5. Evaluate: check whether the answer is supported by the retrieved sources and whether retrieval missed important evidence.

6. A practical mental model

  • Model: learned parameters that map context to predictions.
  • Context: the information currently supplied to the model; it is not the same thing as permanent memory.
  • Retrieval: searches an external corpus and supplies selected evidence.
  • Tool use: lets a system call software or APIs to observe or change the outside world.
  • Evaluation: measures quality on representative tasks instead of relying on a few impressive examples.

Important: an AI model can produce fluent but incorrect statements. For high-impact decisions, verify facts, test the system, and keep humans in the loop.

8. Common AI application patterns

RAG

Retrieve external documents, then provide selected passages as model context. Useful for internal documentation, customer support, and question answering over a private knowledge base.

Classification

Assign a label or score to input, such as ticket routing, sentiment, spam detection, or alert categorization.

Recommendation

Represent users and items as features or vectors, retrieve candidates, then rank them with additional signals.

Agent workflow

Use a model to choose among tools, but constrain it with explicit state, validation, permissions, timeouts, and retry limits.

9. Production checklist

  • Data quality: remove duplicates, track source and freshness, and respect access permissions during retrieval.
  • Evaluation: test retrieval relevance separately from answer quality; include difficult and adversarial examples.
  • Latency and cost: measure embedding, retrieval, model generation, and tool-call latency independently.
  • Reliability: handle model timeouts, unavailable tools, malformed output, and empty search results.
  • Security: treat retrieved documents and model output as untrusted input; do not let prompt text override tool authorization or access controls.
