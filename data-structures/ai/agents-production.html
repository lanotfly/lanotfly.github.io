5. AI Agents & Production — State, Tools, Safety and Evaluation

An AI agent is a system that uses a model to choose actions, observes results, and continues toward a goal. Reliable agents need explicit state and guardrails—not just a model prompt.

1. Basic agent loop

  1. Receive a goal and current context.
  2. Choose an action or tool call.
  3. Validate that the action is allowed and arguments are well formed.
  4. Execute the tool and capture its result.
  5. Update state, evaluate progress, and continue or stop.
state = {"goal": goal, "observations": [], "steps": 0}
while state["steps"] < MAX_STEPS:
    action = model_choose_action(state)
    if action["type"] == "finish":
        break
    validate_permissions(action)
    result = execute_tool(action)
    state["observations"].append(result)
    state["steps"] += 1

This is conceptual pseudocode: a production implementation also needs exception handling, schemas, timeouts, cancellation, and durable logs.

2. Useful CS abstractions

Finite-state machineDefines legal stages and transitions

Append-only logRecords actions and observations for debugging
Retry policyBounds repeated attempts and handles transient errors

3. Guardrails and security

  • Use least-privilege credentials and explicit per-tool authorization.
  • Validate tool arguments against schemas and business rules.
  • Require confirmation for destructive or externally visible actions.
  • Treat model output and retrieved documents as untrusted input.
  • Set timeouts, step limits, budgets, and retry limits.
  • Prevent secrets from entering prompts or logs unnecessarily.

4. Evaluation and observability

Log each step with trace IDs, latency, tool name, outcome, and error category. Evaluate task success, invalid tool calls, recovery behavior, and safety violations. Test adversarial instructions and partial outages, not only the happy path.

5. SRE checklist

  • Define an SLO for completion rate and latency.
  • Measure model latency separately from tool/API latency.
  • Use idempotency keys for retryable writes.
  • Provide cancellation and human handoff.
  • Keep an auditable event history and a rollback path.
  • Fail safely when confidence, permissions, or dependencies are insufficient.
