8. Trie (Prefix Tree)

When to reach for it

Anything about prefixes: autocomplete, spell-check, "find all words starting with…", IP routing, word search on a board. A trie trades space (shared prefixes stored once) for O(L) operations, L = word length — independent of how many words you stored. A hash set can't answer prefix queries.

Complexity

Insert / search / starts-with: O(L). Space: O(total characters) worst case. Each node holds child pointers (dict in Python) plus an end-of-word flag.

Core implementation

class TrieNode:
    __slots__ = ("children", "is_end")

    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.is_end = False


class Trie:
    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True

    def _walk(self, prefix: str) -> TrieNode | None:
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.is_end

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None


trie = Trie()
trie.insert("apple")
assert trie.search("apple") and not trie.search("app")
assert trie.starts_with("app")

Classic interview angle: Word Search II (board + trie)

Build a trie of the target words, then DFS the board, walking the trie as you go — a dead prefix prunes the whole branch. Delete found words from the trie (or clear is_end) to avoid duplicates. Mentioning pruning is the sentence that separates a pass from a strong pass here.

Pitfalls

  • is_end matters: "app" is a prefix of "apple" but not a stored word.
  • Memory: a node per character — for huge alphabets use dict children, not fixed arrays, in Python.
  • Case & character set: clarify lowercase a–z vs full Unicode up front.

Practice

  • [ ] Implement a trie (above) from memory, without looking
  • [ ] Longest word in dictionary built one character at a time
  • [ ] Replace words (shortest root / prefix in a sentence)
  • [ ] Design search autocomplete (trie + top-3 cache per node)

Real-world uses

  • Autocomplete: find words that start with a typed prefix.
  • Spell-checking: test dictionary membership and explore nearby candidates.
  • Routing: longest-prefix matching for IP routing tables.
  • Word puzzles: prune a board search as soon as a character path is not a valid prefix.

Trie patterns

Prefix search

Walk the prefix in O(L); enumerate descendants to return suggestions.

Trie + DFS

For Word Search II, follow board neighbors while simultaneously walking trie edges; prune dead prefixes early.

Compressed trie / radix tree

Merge single-child paths to reduce node count and memory overhead.

Bitwise trie

Store bits instead of letters for tasks such as maximum XOR pair queries.

Complexity and trade-offs

Lookup is usually O(L), where L is the key length, independent of the number of stored keys in the basic model. Memory can be much larger than a hash map because many nodes and child references may be allocated. Use a trie when prefix operations are central; use a hash map for exact-key lookup when prefix search is unnecessary.
