3. Linked List

When to reach for it

Frequent inserts/deletes, no random access needed, "reverse / reorder / detect a cycle in a chain". Interviews love it because it tests pointer care.

Complexity

Access & search O(n); insert/delete O(1) once you hold the node; space O(n), no resizing ever.

Core implementation

from __future__ import annotations
from dataclasses import dataclass

@dataclass
class ListNode:
    val: int
    next: ListNode | None = None

The dummy head trick — never special-case the head again

def delete_value(head: ListNode | None, target: int) -> ListNode | None:
    dummy = ListNode(0, head)
    cur = dummy
    while cur.next:
        if cur.next.val == target:
            cur.next = cur.next.next
        else:
            cur = cur.next
    return dummy.next

Classic interview problem: Reverse a linked list

def reverse(head: ListNode | None) -> ListNode | None:
    prev, cur = None, head
    while cur:
        nxt = cur.next      # save
        cur.next = prev     # flip
        prev, cur = cur, nxt
    return prev

Classic problem 2: Detect a cycle (Floyd's tortoise & hare)

def has_cycle(head: ListNode | None) -> bool:
    slow = fast = head
    while fast and fast.next:
        slow = slow.next          # 1 step
        fast = fast.next.next     # 2 steps — they must meet inside a cycle
        if slow is fast:
            return True
    return False

Finding the middle uses the same two speeds: when fast ends, slow is mid.

Pitfalls

  • Losing the rest of the list: always save cur.next before rewiring.
  • Forgetting the base cases: empty list, single node, cycle.
  • In Python interviews, state the complexity of your operations —

list.pop(0) is O(n), a linked list pop-front is O(1).

Real-world uses

  • LRU cache: combine a hash map with a doubly linked list to move recently used items to the front in O(1).
  • Queues and deques: linked nodes can support operations at both ends, though array-backed deques are often faster in practice.
  • Memory/runtime internals: intrusive lists, free lists, and some schedulers.

Core linked-list patterns

Dummy / sentinel node

Simplifies edge cases when the head may be removed or the list may become empty.

Fast and slow pointers

Find the middle node or detect a cycle in O(n) time and O(1) extra space.

Reverse pointers

Save next before rewiring links; maintain previous, current, and next references.

Merge two lists

Use a dummy head and repeatedly attach the smaller current node. O(n + m) time.

Trade-offs

Inserting or deleting a known node can be O(1), but finding that node is O(n). Lists have pointer overhead and poor cache locality, so they are not automatically faster than arrays. Choose them when link manipulation is the main requirement, not merely because insertion sounds frequent.

Related patterns: recursion, fast/slow pointers and graph traversal.
