5. Tree & Binary Search Tree

Tree families: not all trees are the same

A tree is a hierarchical structure made of nodes and edges. The top node is the root; nodes with no children are leaves. A subtree is a node together with all of its descendants. Trees are useful when data has hierarchy, when we need ordered search, or when we repeatedly ask questions about ranges or prefixes.

Binary tree

Each node has at most two children. It describes a shape, not a sorting rule.

Use it for: expression trees, decision trees, syntax trees, hierarchical relationships, and many recursive interview problems.

Binary Search Tree (BST)

Values in the left subtree are smaller and values in the right subtree are larger (assuming a unique-key convention). Search is O(h), where h is tree height.

Use it for: ordered sets/maps, predecessor/successor queries, and kth-smallest problems. A skewed BST can degrade to O(n).

Balanced search trees

AVL trees keep strict height balance; Red-Black trees use coloring rules to maintain logarithmic height with fewer rotations in many update workloads.

Use it for: ordered maps/sets and database or runtime libraries that need predictable O(log n) lookup, insert, and delete.

Heap (complete binary tree)

A min-heap keeps the smallest item at the root; a max-heap keeps the largest. It is only partially ordered, not a BST.

Use it for: priority queues, job scheduling, Dijkstra's algorithm, top-K, and streaming medians.

Trie (prefix tree)

Edges represent characters or tokens; shared prefixes share paths. Lookup depends mainly on key length L, often O(L).

Use it for: autocomplete, spell-checking, routing prefixes, dictionaries, and word-search problems.

B-tree / B+ tree

A multi-way balanced search tree: nodes hold multiple keys and have many children, keeping the tree shallow.

Use it for: database indexes and filesystems, where a node can map naturally to a disk page or storage block.

Segment tree / Fenwick tree

These tree-based structures organize aggregate information over array ranges. Segment trees are flexible; Fenwick trees are compact for prefix sums and point updates.

Use it for: range sum/min/max queries, repeated updates, and competitive-programming tasks.

Decision / expression tree

Internal nodes represent decisions or operators; leaves represent outcomes or operands.

Use it for: interpreters, compilers, rule engines, decision support, and evaluating mathematical expressions.

Common tree algorithms

  • DFS traversals: preorder (root-left-right), inorder (left-root-right), and postorder (left-right-root). Inorder traversal of a BST visits keys in sorted order.
  • BFS / level order: use a queue to visit nodes by depth. Useful for shortest-depth questions, level averages, and nearest-leaf problems.
  • Height and depth: height is the longest downward path to a leaf; depth is the distance from the root. Watch whether the problem counts edges or nodes.
  • Lowest common ancestor: find the deepest node that is an ancestor of both target nodes.
  • Tree DP: return information from child subtrees, such as height, diameter, or whether a subtree satisfies a condition.
  • Serialize / deserialize: encode a tree into a sequence and reconstruct it, often using preorder plus null markers or level-order traversal.

Interview habit: state whether the tree is arbitrary, a BST, balanced, or complete before claiming a complexity. Many tree algorithms are O(n) because every node is visited once; recursive space is O(h), where h is the height.

When to reach for it

Hierarchical data, "traverse", divide-and-conquer on subtrees, ordered data with O(log n) search/insert/delete (a BST: left < node < right).

Complexity

Balanced tree: search/insert/delete O(log n), traversal O(n). Unbalanced (degenerate) tree: everything degrades to O(n) — always mention this.

Core implementation & traversals

from __future__ import annotations
from collections import deque
from dataclasses import dataclass

@dataclass
class TreeNode:
    val: int
    left: TreeNode | None = None
    right: TreeNode | None = None

def inorder(root: TreeNode | None) -> list[int]:
    """Left → Root → Right. On a BST this returns sorted order."""
    if not root:
        return []
    return inorder(root.left) + [root.val] + inorder(root.right)

def level_order(root: TreeNode | None) -> list[list[int]]:
    """Breadth-first, one list per level — BFS with a queue."""
    if not root:
        return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:  queue.append(node.left)
            if node.right: queue.append(node.right)
        result.append(level)
    return result

Classic interview problem: Lowest common ancestor (BST)

def lca_bst(root: TreeNode, p: int, q: int) -> TreeNode:
    node = root
    while node:
        if p < node.val and q < node.val:
            node = node.left          # both in the left subtree
        elif p > node.val and q > node.val:
            node = node.right         # both in the right subtree
        else:
            return node               # split point = the LCA
    return node

Classic problem 2: Validate a BST

Pass the allowed (low, high) range down — checking only parent vs children is not enough.

def is_valid_bst(root: TreeNode | None,
                 low: float = float("-inf"),
                 high: float = float("inf")) -> bool:
    if not root:
        return True
    return (low < root.val < high
            and is_valid_bst(root.left, low, root.val)
            and is_valid_bst(root.right, root.val, high))

Pitfalls

  • Preorder / inorder / postorder mix-ups: name the root's position in the sequence.
  • Python recursion limit on skewed trees — mention an iterative stack version.
  • "Kth smallest in BST" = inorder traversal, stop at k. Don't sort.
